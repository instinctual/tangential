Introduction
This document should be used in association with the TUBE API document. The purpose of
this is to explain some changes that have been made between releases but do not
necessarily appear in the TUBE document. These notes should indicate what you need to do
when upgrading to the latest version of the TUBE Hub and Mapper.

It is important that any essential changes detailed below are made before using the
latest Hub with your application. Such essential changes are indicated in red.

Version 2.6
Added details of the option for Ripples to emulate element-Tk panels so they can be used
with applications that currently only support element panels.

The option is selected via the control map settings menu in the Tangent Mapper application
and is set per application. If emulation is active, the Ripple panel will appear to the
application as if it was a standard element-Tk and use any control mappings set on the
element-Tk. If emulation is not active, the panel appears as a standard Ripple panel with its
own set of control mappings.

The ‘Save As Defaults’ option in the Developer menu has been improved to automatically
update the application’s controls XML file with the required mode definition section. In earlier
versions this had to be done manually to complete the conversion of user map data to
default map data.
With the new default mode processing, once the first set of panel default files are generated,
it is important all future changes must be made based on the these new defaults, and not re-
using the original user control map.

If you reload your user control map to modify the layout you will end up with duplicate
modes, with the user defined modes sitting alongside the ones now defined for the
application in the controls file.

Version 1.9
This pack includes the OSX version of the Panel Mapper. To use this to generate Map files
for use on Windows or Linux it is necessary to use our MockApplication utility to make the
Mapper think that it is talking to your application.

Inside the MockApplication directory there is a sub-directory sys. Place a copy of your
controls.xml and default map files in here.

Run the Hub, MockApplication and Panel Mapper.

In the Mapper, you may first need to change the System Panel Configuration to reflect the
panel types which you wish to generate Maps for.

You will see that the Mapper shows the Mappings defined in your default Maps. Now you
can make changes and save out an altered Map file. As the Mapper cannot overwrite the
Default Map files User Maps are generated instead. Each User Map contains the mappings
for all panels which are defined as active. This is a single file so you will need to copy the
appropriate lines of XML from the User Map file into your default Map files for each panel
type.

The MockApplication supplied with this version of the Dev Pack will save the User Map files
into: ~/Library/Application Support/Tangent/Hub/MockAppName/<mapname>.xml

Version 1.5
Configuration file: panel-list.xml

This file will normally be created by the Mapper Utility when it is first run. However, until this
is available for your platform a hand-built version must be created in the specified directory.
Without this file Hub versions 0.1.3 onwards will report that no panels are configured for
connection and will not attempt to connect to any panels.

    Windows XP:
      C:\Documents and Settings\All Users\Application Data\Tangent\Hub\panel-list.xml


    Windows 7:
      C:\ProgramData\Tangent\Hub\panel-list.xml

    Linux:
       /var/opt/Tangent/Hub/panel-list.xml

    OS X:
      /Library/Application Support/Tangent/Hub/panel-list.xml

A sample panel-list.xml file has been supplied with this package so please copy it into the
relevant directory and edit as required.

This file is used to tell the hub what panels to expect to be connected, their Serial Numbers
and the Number tag to associate with each panel – if applicable.

The Panel Nodes may have an additional two attributes:
   • number (attribute)


                                                                                                7
                                                        TUBE Development Support 3.12

   •   serial (attribute)

For the situation when there is only one panel of each type is configured for use it is not
necessary to complete either the serial or number attributes as these will be automatically
configured by the Hub when panels are detected as connected.
For the situation when multiple panels of the same type are required then both the serial
and number attributes are mandatory.

The number attribute defines the mapping which is to be applied to this panel. Either from
the system default map for the file type or from the user map file which has been customised
by the operator. The value should start be a unique positive integer. See the Map XML
section in the TUBE document for more details of how this value is used.

The serial attribute associates a particular panel’s serial number to the number attribute.
This means that each panel will always have the same mapping applied. Without this it
would be undetermined which panel would receive which mapping.

Example syntax:
    <Panel type="Element-Bt" number="1" serial="00000042"/>
    <Panel type="Element-Bt" number="2" serial="00000043"/>


InitiateComms

An extra field has been added to the InitiateComms command: protocolRev.
This is now the first field in the command so it is important that the decode routine within
your application is altered to handle this.

Inter Process Comms streamlining

We have improved the handling of IPC data by combining multiple commands into single
messages wherever possible. This is particularly relevant when trackerballs are moved
causing two encoders to change at the same time. In previous versions this resulted in two
separate messages to be generated, one for each encoder. Now both encoder change
commands are sent in the same message.
